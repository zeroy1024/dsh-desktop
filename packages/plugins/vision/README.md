# @dsh-desktop/vision

为不接受图片输入的模型补充图片理解能力。主会话的 Provider 和模型保持不变；
插件通过独立配置的视觉 API 生成文字证据，不覆盖原始会话图片。

## 转写方式

`vision.transcriptionMode` 支持两种模式，设置卡可随时切换；保存后影响后续操作。
已有配置没有该字段时也使用新的默认值，不需要修改会话或手动迁移附件。

| 配置 | 行为 |
| --- | --- |
| `on-demand`（默认，按需转写） | 当前活动回合新加入的图片自动转写；历史图片复用通用证据，没有证据则提供引用，由模型需要时调用 `vision_analyze_image`。 |
| `immediate`（立即转写） | 保留原有流程：本次有效上下文中的全部图片在发送前转写，完成后再调用主模型。 |

新图通过当前 Agent 的 `turn/start` 和消息事件身份判定，不按时间或最新一条 user
消息猜测。此前回合、恢复与分叉继承的图片属于历史图片；压缩、撤回已移出有效
上下文的图片不会被重新引入。本轮产生的大量新截图仍需要自动转写；按需模式解决
的是历史图片集中补做，不保证任何多图请求都能立即响应。

切换到文本模型后，历史截图不需要用户逐张操作：请求先携带已有证据或明确标注
“尚未分析”的引用，模型可通过工具读取所需图片。引用只含附件派生身份、消息身份
和已有来源信息，不伪造内容摘要，也不公开附件存储路径。

按需投影要求存在可靠的当前会话，且本次请求允许调用图片分析工具（包括 PTC
的 `run_code` SDK）。无工具的摘要调用、独立 LLM 调用等自动回退为立即转写，
不生成无法读取的图片引用。插件没有就绪或未配置时不接管图片。

## 图片分析工具

`vision_analyze_image({ image_ref, question? })` 返回图片引用、分析文字和 `cached`
标记。省略问题生成通用描述；提供问题可以重新检查此前描述遗漏的细节。工具结果
通过上游标准工具结果记录和显示，不创建额外 user 消息。

工具只读取调用方当前有效会话中的图片引用，在读取附件和查询证据前验证归属。

工具使用 dsh 原生 `defineTool()` 编译参数和输出声明，再注册到工具目录；不要将
参数简写直接交给 `tools.register()`。对外参数必须是 `type: object` 的 JSON Schema，
`image_ref` 必填、`question` 可选。回归测试覆盖真实工具目录与 Chat、Responses、
Anthropic 三种 SDK 请求序列化，并验证非法参数在图片读取和网络请求前被拒绝。
不支持任意路径、URL 或其他会话的引用。被撤回或压缩移出上下文的引用会返回明确
错误。普通工具模式和 PTC 模式都通过上游工具执行器运行，支持取消及插件卸载。
上游 `read_image` 保持不变；该工具仍负责文件图片读取，不被本插件覆盖。

## 能力判定

只在请求含图片时检查目标 Provider/模型的输入能力，不按名称或家族猜测。

| `inputModalities` | 行为 |
| --- | --- |
| 包含 `image` | 原生图片路线，直接发送原图，不调用视觉桥 |
| 明确存在但不包含 `image` | 按所选转写模式生成文本请求 |
| 成功解析但未声明 | 默认 `unknownCapabilityPolicy: passthrough`；显式 `bridge` 才桥接 |
| 能力解析失败 | 保留原错误，不调用辅助视觉 API |

准入服务不伪装模型原生能力。正式 `registerInputTransform` 钩子在 adapter dispatch
前投影一次请求；本次工具名称清单用于判断图片引用能否被读取。旧运行时仅在没有
正式钩子时使用 `llm/stream` + MARKER 兼容路径，不重复注册两套拦截。
旧配置键 `upstream`、`families`、`models` 继续被无害忽略。插件只处理图片，不声明视频能力。

## 证据与生命周期

成功证据经 `storageDomain` 保存到插件拥有的 `vision_evidence` 域。记录会话、附件、
描述类别、生成配置版本、文字与时间，不保存密钥或图片字节。记录以会话隔离：
不同会话和分叉不会直接共享带上下文的描述。

- 按需通用证据不加入最新用户问题，采用稳定的描述提示词。
- 定向分析将 trim 后的问题加入缓存身份，不将问题答案作为通用描述。
- 立即模式保留 `focusHint` 行为及首次关注点复用语义，与通用证据分开保存。
- 主模型名称和转写模式不参与生成身份；视觉模型、端点、提示词及相关参数参与。
- 内存 LRU 由现有 `cacheSize` 控制；持久记录限制为 64 MiB，按最近使用顺序淘汰。
  重启或内存淘汰后可复用仍在持久存储中的证据；持久淘汰后需要时重新分析。
- 存储初始化后再判断持久命中；存储错误降级为内存复用并记录诊断，损坏记录视为未命中。
- 两种模式和工具共享插件实例级队列，最多同时执行 2 个视觉请求。同一图片与分析
  配置的在途任务共享；取消一个调用方不影响其他调用方，最后一个离开才取消工作。
- 失败、超时与取消不进入成功缓存。立即转写及新图自动转写失败时保留明确失败文字；
  按需工具失败通过正常工具错误返回。单图超时沿用 `requestTimeoutMs`（默认 90 秒）。
- 设置修改后新操作使用新配置；旧操作可完成但不能回填到新的在途任务。卸载取消任务、
  排空持久写入并关闭存储。不会后台补做全部历史图。

## 配置与凭据

API key 通过 credentials service 管理，不写入普通 settings，也不回显。新安装使用
内部引用 `DSH_VISION_API_KEY`；隐藏的 legacy `apiKeyEnv` 显式引用继续优先使用。
没有自定义引用时兼容按 `DSH_VISION_API_KEY` → `SELF_API_KEY` 读取。挂载 credentials
service 时只通过它解析；只有该服务不可用的最小组合才读取 launch environment。

客户端设置卡支持暂存、保存、放弃、重置和 revision-fenced 写入。关闭插件或修改
配置无需改写旧会话，原图仍可供支持图片的模型使用。

## Model Experience

### What the model sees

图片模型看到原图。文本模型在立即模式下看到原位置的 `[图片证据]`；按需模式下
看到证据或“尚未分析”的引用以及工具读取说明。需要细节时调用图片分析工具，取得
文字结果后继续工作。引用本身不表示图片已经被理解。

### Token effect

历史图片引用比逐图完整转写更小；转写文本仍受现有单图字符限制。工具分析增加一次
工具交互及文字结果。缓存命中避免辅助视觉 API 调用，不等于这些文字不消耗主模型
上下文。当前新图和立即模式下的多图输入仍可能产生较多证据文本。

### KV Cache effect

原始会话保持稳定，但按模型投影出的请求前缀可能变化：图片变成引用、引用获得证据，
或切换转写配置，都可能改变主模型收到的前缀。持久证据提高派生文字的可复用性，
不保证不同模型或不同投影之间复用 Provider 的 KV cache。

## Known Limitations and Deferred Work

- 按需模式依赖模型正确选择读取工具；没有读取过的图片内容不能凭引用推断。
- 不新增批量进度面板、历史图片自动裁剪、失败退避或后台预转写。按需分析使用标准工具 UI。
- 被压缩或撤回移出有效上下文的图片不能用旧引用直接读回；不提供存档图片检索工具。
- 无 storageDomain 的最小运行时仅支持进程内缓存；没有会话或工具上下文时回退立即转写。
- 单图文字证据是有损描述；需要核对新细节时应提供 question 再分析原图。
